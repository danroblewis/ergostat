# golden-file-ui-tests: Page tests compare against saved reference outputs that a program regenerates

Golden-file tests: a page's rendered structure (or a screenshot) is saved as a reference file; the test compares against it, and an intended change regenerates the reference by a command instead of rewriting assertions by hand. Start with the dashboard's panels.
Done: 1. A regenerate command and a test that fails on an unintended change. 2. Diffs are readable in review.

The owner's decisions behind this (2026-11-23): more delivered work per AI dollar; tests exist for regressions; prefer program and rule checks over AI review; any path that checks less before merge needs a way to find and revert regressions on main. General parts go in ergostat's core as options a model declares (off unless declared, naming no gaps or software); this factory is the first user. Do not measure or change the live instance in the session: the coordinator applies changes.

## Where it stopped

Round 1, built. What is there:

- `tests/golden.py`: `STRUCTURE` reads a page's rendered structure into text, one line per element, indented: tag
  and sorted classes, an allowlist of attributes (no style, size or pixel position, so fonts and platforms do not
  move it), a Dashboard cell's grid place (`at=x,y size=wxh`, from its `--x/--y/--w/--h`), its own words; a hidden
  element is one line with no children. `compare(name, text)` checks it against `tests/golden/<name>.txt`.
- Done 1, the regenerate command: `uv run python scripts/suite_watch.py -- uv run --with playwright==1.63.0 python -m
  tests.golden` runs the golden test files serially with `ERGOSTAT_GOLDEN=update`, so each test writes what it drew,
  and prints which references are new or changed. Its no-browser half is tested in `tests/test_golden.py`
  (`test_the_regenerate_command_runs_the_golden_tests_in_update_mode_and_says_what_changed`,
  `..._says_when_the_tests_did_not_pass`). In update mode a missing Playwright fails the run; it never skips.
  The command itself was not run here, because it is not among this session's allowed commands. The reference was
  made by the test's own missing-file path instead: a missing reference is written and the test fails, so nothing
  passes with no reference to compare.
- Done 1, the test that fails on an unintended change:
  `tests/test_golden_pages.py::test_the_default_dashboards_panels_match_their_reference` draws the default Dashboard
  from test_dashboard_page's fake fields and answers, with a fixed clock, UTC, en-US, pixel ratio 1 and a viewport
  tall enough that every panel is drawn. It compares the 25 panels against `tests/golden/dashboard-default-panels.txt`.
  It passed on two runs in a row. I broke the page three ways to see whether it fails:
  - `WORDS.empty` "No data" changed to "No values" in panels.js: it failed, with the two candlestick and phase-portrait
    lines in the diff.
  - `DASH_COLUMNS.s` 4 changed to 3 in dashboard.js: it failed, with every moved panel's `at=`/`size=` in the diff.
  - `chip.hidden = false` in panels.js: it passed. CSS hides an empty unit chip and a stat panel's chip anyway, so
    nothing on the page changed. The test reads what is shown, not the code.
  Each break was reverted with `git restore`.
- Done 2, readable diffs: the reference is plain text, one element per line, and each panel's cell line sits at column
  0. So `git diff`'s default hunk header names the panel (`@@ ... @@ section.dash-cell at=4,50 ... aria-label="widget:
  time in ready, open to close"`), and the test's failure prints a unified diff with the same header, plus the command
  to regenerate. Tested by `test_a_change_fails_with_a_diff_that_names_its_root_and_the_command`.
- So that a gate runs it: `tests/test_golden_pages.py` is added to `[suites] browser` in dev/factory.toml, and it,
  `tests/golden.py` and `tests/golden/*` to `browser_paths`. Without this the test would only skip in the unit suite
  (lesson 9). `test_every_golden_test_file_is_in_the_browser_suite` pins this. CLAUDE.md's and docs/DEVELOPMENT.md's
  browser command and standard runs say the same. This makes a sixth browser file. It is one line to take out if the
  owner prefers the test inside one of the existing five.
- Nothing is a model option. The owner's rule puts general parts in ergostat's core as options a model declares, but
  golden files are the repository's own test tooling, with no runtime part, so the rule does not apply here.
- Two things on main that the reference records as they are drawn now, and which I left alone (lesson 13):

    properties of undefined (reading 'id')".
  - An empty panel's message holds a stray "null" text node (`div.is-empty.panel-message "null"`).
  A fix for either changes the reference, and the change is then regenerated by the command above.
